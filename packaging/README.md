# Desktop packaging

The release artifacts are **one bundle per system and architecture**, not one archive
per component. Each bundle contains both the desktop app and the headless CLI:

| System | Bundle |
|---|---|
| Windows x64 | `5do-<version>-win-x64.zip` |
| Windows arm64 | `5do-<version>-win-arm64.zip` |
| Linux x64 | `5do-<version>-linux-x64.tar.gz` |
| Linux arm64 | `5do-<version>-linux-arm64.tar.gz` |
| macOS x64 | `5do-<version>-osx-x64.dmg` |
| macOS arm64 | `5do-<version>-osx-arm64.dmg` |

For example, version `1.7.0` produces `5do-1.7.0-win-arm64.zip` or
`5do-1.7.0-osx-arm64.dmg`. The version is read from `Directory.Build.props` by default;
pass `-Version` to `package-bundle.ps1` to override it. On macOS the script also builds a
`.pkg`; the internal `.tar.gz` remains the CI extraction/smoke intermediate.

## Requirements

The bundles are **framework-dependent**. The .NET 10 runtime must be installed on the
user's machine; no .NET runtime is embedded in the executables or copied into the
bundle.

- Download: <https://dotnet.microsoft.com/download/dotnet/10.0>
- The apphosts print the standard ".NET runtime not found" message when the runtime is
  missing.

## Layout

```text
FiveDo.Cli[.exe]              single-file apphost
FiveDo.Frontend.Avalonia[.exe] single-file apphost
OpenAL32.dll / soft_oal.dll   native OpenAL Soft (Windows)
libopenal.so / libopenal.dylib
libSkiaSharp.*, av_libglesv2.dll, ...
README.md
whatsnew.md
LICENSE
THIRD-PARTY-NOTICES.md
docs/Licensing.md
docs/ReleaseLegalReview.md
docs/OpenALSoft.md
docs/OpenAL-Soft-COPYING.txt
docs/ReleaseNotes-*.md
PACKAGE.txt
```

The apphosts are published with:

```text
--self-contained false
-p:PublishSingleFile=true
-p:PublishTrimmed=false
```

Each app is a single executable, and the .NET runtime is resolved from the machine's
installed runtime. The bundle deliberately does **not** contain a `runtime/` folder.

### XML documentation files

The publish output contains `FiveDo.*.xml` files generated by
`GenerateDocumentationFile=true`. They are XML documentation comments for IDEs and are
**not required at runtime**. `packaging/package-bundle.ps1` removes every `*.xml` file
(and every `*.pdb`) from the bundle.

### Native libraries

OpenAL Soft is LGPL-2.0-or-later and must remain replaceable. Skia and ANGLE also ship
as native assets. Keeping them beside the apphosts preserves relinking/replacement
rights and avoids extraction to a temporary directory.

## Build a bundle

```powershell
$rid = 'win-x64'

dotnet publish src/FiveDo.Cli/FiveDo.Cli.csproj -c Release -r $rid `
  --self-contained false -p:PublishSingleFile=true -p:PublishTrimmed=false `
  -m:1 -o "artifacts/bundle/$rid/cli"

dotnet publish src/FiveDo.Frontend.Avalonia/FiveDo.Frontend.Avalonia.csproj `
  -c Release -r $rid --self-contained false -p:PublishSingleFile=true `
  -p:PublishTrimmed=false -m:1 -o "artifacts/bundle/$rid/frontend"

pwsh -NoProfile -File packaging/package-bundle.ps1 `
  -Rid $rid `
  -CliPublishDirectory "artifacts/bundle/$rid/cli" `
  -FrontendPublishDirectory "artifacts/bundle/$rid/frontend" `
  -OutputDirectory "artifacts/bundles"
```

The script merges the two publish outputs, verifies that shared files are identical,
removes PDB/XML files, copies the README/license/notices/whatsnew/release notes, and
writes `PACKAGE.txt`, the versioned bundle, and `SHA256SUMS.txt`. On macOS it also runs
`packaging/macos/build-macos-package.sh` against the staged bundle and adds the DMG hash
to `SHA256SUMS.txt`.

For local release copies, use:

```powershell
-OutputDirectory src/FiveDo.Frontend.Avalonia/bin/Release
```

On Windows, build the Windows and Linux bundles directly. Build the macOS DMG on a macOS
host (or download it from the CI artifact); the Windows cross-publish of `osx-*` is only
suitable for the intermediate tarball and architecture check.

## Installers and file associations (UX-16)

The portable bundles remain the primary release artifact. The packaging directory now
also contains unsigned installer/package scaffolding for each desktop platform. Signing
and notarization are opt-in and only run when the certificate or Apple account is
available.

### Windows (Inno Setup)

`packaging/windows/5do.iss` installs both apphosts, creates Start Menu/desktop
shortcuts, and registers a `5DO.Disc` ProgID for `.iso`, `.cue`, `.chd`, and `.bin`
plus `5DO.Playlist` for `.m3u`. Associations use `HKA`, so an unelevated install writes
to `HKCU` and an elevated install writes to `HKLM`.

```powershell
# Build the win-x64 bundle first
pwsh -NoProfile -File packaging/windows/build-installer.ps1 `
  -BundleDirectory artifacts/bundle/win-x64 `
  -Architecture x64 `
  -OutputDirectory artifacts/installers

# Optional Authenticode signing through Inno Setup's sign-tool hook
pwsh -NoProfile -File packaging/windows/build-installer.ps1 `
  -BundleDirectory artifacts/bundle/win-x64 `
  -SignCommand 'signtool.exe sign /fd SHA256 /tr http://timestamp.digicert.com /td SHA256 /a $f'
```

Requires Inno Setup 6 (`ISCC.exe`). The output is
`5do-<version>-win-x64-setup.exe` plus a `.sha256` file. `win-arm64` uses
`-Architecture arm64`.

### Linux (.deb, .rpm, desktop entry, MIME)

The Linux packages install the apphosts under `/opt/5do`, add `/usr/bin/5do` and
`/usr/bin/5do-cli`, install the desktop entry and SVG icon, and register the
`application/x-3do-disc` MIME type with `*.iso`, `*.cue`, `*.chd`, and `*.bin` globs.

```sh
bash packaging/linux/build-deb.sh \
  --bundle artifacts/bundle/linux-x64 --rid linux-x64 --version 1.6.0 \
  --output artifacts/installers

bash packaging/linux/build-rpm.sh \
  --bundle artifacts/bundle/linux-x64 --rid linux-x64 --version 1.6.0 \
  --output artifacts/installers
```

The scripts require `dpkg-deb` or `rpmbuild`. Open the installed `5do` entry or a
`.iso`/`.cue`/`.chd` file to launch the frontend with the disc path.

### macOS (.app, .dmg, .pkg)

`packaging/macos/build-macos-package.sh` creates a `5DO.app` with an `Info.plist`
document type/UTI for the disc extensions, a drag-to-Applications `.dmg`, and a
`.pkg`. Without `--sign-identity` the result is unsigned; with a Developer ID it is
hardened and optionally notarized.

```sh
bash packaging/macos/build-macos-package.sh \
  --bundle artifacts/bundle/osx-arm64 --rid osx-arm64 --version 1.6.0 \
  --output artifacts/installers \
  --sign-identity "Developer ID Application: Example (TEAMID)" \
  --notary-profile "5do-notary"
```

Signing uses `codesign --options runtime` with the JIT entitlements in
`packaging/macos/entitlements.plist`. Notarization uses `notarytool` and staples the
ticket to both artifacts. Without credentials, keep the unsigned `.dmg`/`.pkg` or use
the portable tarball.

## CI

`.github/workflows/build-bundle.yml` builds the Windows and Linux bundles on their
native runners and cross-publishes the macOS x64 bundle on Ubuntu; the macOS bundle is
validated as Mach-O x86_64 rather than executed. The runners install .NET 10, which also
proves the framework-dependent apphosts work. `.github/workflows/release.yml` publishes
the bundles and `SHA256SUMS.txt` to the GitHub release. The docs workflow publishes the
documentation site and the wiki.

The Windows/Linux archives and the macOS DMG are the portable bundles; the installer
scripts above are additive. Unsigned installers can be produced locally and in CI.
Authenticode signing, Developer ID signing, and notarization remain conditional on valid
certificates and an Apple developer account; without them the portable bundles and
unsigned installers are the release artifacts.
