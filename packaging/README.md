# Desktop packaging

The release artifacts are **one bundle per system and architecture**, not one archive
per component. Each bundle contains both the desktop app and the headless CLI:

| System | Bundle |
|---|---|
| Windows x64 | `5do-<version>-win-x64.zip` |
| Windows arm64 | `5do-<version>-win-arm64.zip` |
| Linux x64 | `5do-<version>-linux-x64.tar.gz` |
| Linux arm64 | `5do-<version>-linux-arm64.tar.gz` |
| macOS arm64 | `5do-<version>-osx-arm64.dmg` |

For example, version `1.8.0` produces `5do-1.8.0-win-arm64.zip` or
`5do-1.8.0-osx-arm64.dmg`. The version is read from `Directory.Build.props` by default;
pass `-Version` to `package-bundle.ps1` to override it. On macOS the script also builds a
`.pkg`; the internal `.tar.gz` remains the CI extraction/smoke intermediate.

## Requirements

The bundles are **self-contained**. The .NET 11 runtime is embedded in each
single-file executable; no separate runtime install is required and no `runtime/`
folder is staged.

- Download: <https://dotnet.microsoft.com/download/dotnet/11.0>
- The apphosts print the standard ".NET runtime not found" message when the runtime is
  missing.

## Layout

```text
FiveDo.Cli[.exe]              single-file apphost
FiveDo[.exe] single-file apphost
OpenAL32.dll / soft_oal.dll   native OpenAL Soft (Windows)
libopenal.so / libopenal.dylib
libSkiaSharp.*, av_libglesv2.dll, ...
5do.desktop                   portable launcher (Linux, Exec=FiveDo)
packaging/                    packager reference files (Linux only)
  ├── 5do.desktop             installed launcher (Exec=5do)
  ├── 5do.xml                 shared-mime-info definition
  ├── io.github.purelogiccode.FiveDO.metainfo.xml   AppStream metadata
  ├── 5do.svg                  scalable icon
  └── 5do-256.png              256 px icon
README.md
whatsnew.md
LICENSE
THIRD-PARTY-NOTICES.md
docs/Licensing.md
docs/ReleaseLegalReview.md
docs/OpenALSoft.md
docs/OpenAL-Soft-COPYING.txt
docs/ReleaseNotes-*.md
PACKAGE.txt
```

The Windows bundle must contain **both** `OpenAL32.dll` and `soft_oal.dll`;
`OpenAL32.dll` is the name Silk.NET.OpenAL passes to the loader. `package-bundle.ps1`
and the bundle workflow reject an archive without the loader-named runtime.

The apphosts are published with:

```text
--self-contained false
-p:PublishSingleFile=true
-p:PublishTrimmed=false
```

Each app is a single executable, and the .NET runtime is resolved from the machine's
installed runtime. The bundle deliberately does **not** contain a `runtime/` folder.

### XML documentation files

The publish output contains `FiveDo.*.xml` files generated by
`GenerateDocumentationFile=true`. They are XML documentation comments for IDEs and are
**not required at runtime**. `packaging/package-bundle.ps1` removes every `*.xml` file
(and every `*.pdb`) from the bundle.

### Native libraries

OpenAL Soft is LGPL-2.0-or-later and must remain replaceable. Skia and ANGLE also ship
as native assets. Keeping them beside the apphosts preserves relinking/replacement
rights and avoids extraction to a temporary directory.

## Build a bundle

```powershell
$rid = 'win-x64'

dotnet publish src/FiveDo.Cli/FiveDo.Cli.csproj -c Release -r $rid `
  --self-contained false -p:PublishSingleFile=true -p:PublishTrimmed=false `
  -m:1 -o "artifacts/bundle/$rid/cli"

dotnet publish src/FiveDo.Frontend.Avalonia/FiveDo.Frontend.Avalonia.csproj `
  -c Release -r $rid --self-contained false -p:PublishSingleFile=true `
  -p:PublishTrimmed=false -m:1 -o "artifacts/bundle/$rid/frontend"

pwsh -NoProfile -File packaging/package-bundle.ps1 `
  -Rid $rid `
  -CliPublishDirectory "artifacts/bundle/$rid/cli" `
  -FrontendPublishDirectory "artifacts/bundle/$rid/frontend" `
  -OutputDirectory "artifacts/bundles"
```

The script merges the two publish outputs, verifies that shared files are identical,
removes PDB/XML files, copies the README/license/notices/whatsnew/release notes, and
writes `PACKAGE.txt`, the versioned bundle, and `SHA256SUMS.txt`. On macOS it also runs
`packaging/macos/build-macos-package.sh` against the staged bundle and adds the DMG hash
to `SHA256SUMS.txt`.

For local release copies, use:

```powershell
-OutputDirectory src/FiveDo.Frontend.Avalonia/bin/Release
```

On Windows, build the Windows and Linux bundles directly. Build the macOS DMG on a macOS
host (or download it from the CI artifact); the Windows cross-publish of `osx-*` is only
suitable for the intermediate tarball and architecture check.

## Installers and file associations (UX-16)

The portable bundles remain the primary release artifact. The packaging directory now
also contains unsigned installer/package scaffolding for each desktop platform. Signing
and notarization are opt-in and only run when the certificate or Apple account is
available.

### Windows (Inno Setup)

`packaging/windows/5do.iss` installs both apphosts, creates Start Menu/desktop
shortcuts, and registers a `5DO.Disc` ProgID for `.iso`, `.cue`, `.chd`, `.bin`, `.cdi`, and `.nrg`
plus `5DO.Playlist` for `.m3u`. Associations use `HKA`, so an unelevated install writes
to `HKCU` and an elevated install writes to `HKLM`.

```powershell
# Build the win-x64 bundle first
pwsh -NoProfile -File packaging/windows/build-installer.ps1 `
  -BundleDirectory artifacts/bundle/win-x64 `
  -Architecture x64 `
  -OutputDirectory artifacts/installers

# Optional Authenticode signing through Inno Setup's sign-tool hook
pwsh -NoProfile -File packaging/windows/build-installer.ps1 `
  -BundleDirectory artifacts/bundle/win-x64 `
  -SignCommand 'signtool.exe sign /fd SHA256 /tr http://timestamp.digicert.com /td SHA256 /a $f'
```

Requires Inno Setup 6 (`ISCC.exe`). The output is
`5do-<version>-win-x64-setup.exe` plus a `.sha256` file. `win-arm64` uses
`-Architecture arm64`.

### Linux (.deb, .rpm, AppImage, Flatpak, desktop entry, MIME, AppStream)

The Linux packages install the apphosts under `/opt/5do`, add `/usr/bin/5do` and
`/usr/bin/5do-cli`, install the desktop entry, a 256 px and SVG icon, the AppStream
metainfo, and the `application/x-3do-disc` MIME type with `*.iso`, `*.cue`, `*.chd`,
`*.bin`, `*.cdi`, and `*.nrg` globs. The bundles are self-contained, so the packages
depend on the X11/fontconfig/freetype/GL libraries only — never on a
`dotnet-runtime` package.

```sh
bash packaging/linux/build-deb.sh \
  --bundle artifacts/bundle/linux-x64 --rid linux-x64 --version 1.12.0 \
  --output artifacts/installers

bash packaging/linux/build-rpm.sh \
  --bundle artifacts/bundle/linux-x64 --rid linux-x64 --version 1.12.0 \
  --output artifacts/installers

APPIMAGETOOL=/path/to/appimagetool/AppRun \
bash packaging/linux/build-appimage.sh \
  --bundle artifacts/bundle/linux-x64 --version 1.12.0 \
  --output artifacts/installers --name 5do-x86_64.AppImage

bash packaging/linux/build-flatpak.sh \
  --bundle artifacts/bundle/linux-x64 --rid linux-x64 --version 1.12.0 \
  --output artifacts/installers
```

The scripts require `dpkg-deb` (dpkg), `rpmbuild` (rpm-build), `appimagetool`, and
`flatpak` plus `flatpak-builder`. `build-flatpak.sh` writes `5do-<arch>.flatpak` from
`packaging/linux/io.github.purelogiccode.FiveDO.yml`, installs the
`org.freedesktop.Platform//26.08` runtime/SDK from Flathub when it is missing (pass
`--no-install-deps` to skip), and keeps the OSTree repository with `--repo-dir` for a
self-hosted Flatpak repository. Open the installed `5do` entry or a
`.iso`/`.cue`/`.chd`/`.cdi`/`.nrg` file to launch the frontend with the disc path.

#### Linux signing

Linux has no OS-level signature for an ELF binary or a `.deb`. Trust is anchored in the
5DO GPG key that signs `SHA256SUMS-linux.txt` and a detached `.asc` for every release
asset.

```sh
# Detached signatures for every release asset plus the public keyring.
bash packaging/linux/sign-artifacts.sh \
  --key-id "$LINUX_GPG_KEY_ID" \
  --keyring-out artifacts/signing/5do-archive-keyring.gpg \
  artifacts/installers
```

The artifacts are published as GitHub release assets; users install the downloaded
package directly (`sudo apt install ./5do_<version>_amd64.deb`), so no repository is
hosted.

`.github/workflows/linux-packages.yml` runs the builds and the signing after
`build-bundle.yml` and is called by `release.yml`. It also installs the generated
`.deb`, runs the CLI self-test and `5do doctor`, and removes the package again. Signing
is skipped with a warning when the `LINUX_GPG_PRIVATE_KEY` secret is absent.

#### Optional package repositories

`build-apt-repo.sh` and `build-rpm-repo.sh` can turn downloaded release files into a
signed `apt`/`dnf` repository if you operate a mirror. This is optional and is not part
of the 5DO release pipeline. The scripts take `--repo-dir`, `--base-url`, and
`--key-id`; keep every release in the pool so pinned versions stay installable.

`--gpgcheck 0` in the RPM example is for a mirror whose packages are not header-signed;
run `build-rpm.sh --sign-key` (or configure `rpmsign` in CI with a passphrase-less key)
to sign the package headers, then publish with `--gpgcheck 1`.

[docs/LinuxDistribution.md](../docs/LinuxDistribution.md) covers verification,
mirroring, and the announcement channels.

#### AUR package

`packaging/linux/aur/` holds the reference `5do-bin` PKGBUILD and the submission steps.
It repacks the released tarball and installs the desktop, MIME, metainfo, and icon files
from the bundle's `packaging/` directory.

#### AppStream metadata

`packaging/linux/io.github.purelogiccode.FiveDO.metainfo.xml` supplies the component
name, summary, screenshots, release, OARS rating, and categories that GNOME Software,
KDE Discover, and Flathub display. `appstreamcli validate --no-net` runs in CI. Keep its
`<release version="...">` entry in sync with `Directory.Build.props` on every version
bump. The `project_license` is a `LicenseRef-*` identifier because the FreeDO modified
LGPL is not an SPDX-listed license; if a validator rejects the custom reference, use
`LicenseRef-proprietary`, the Flathub convention for non-free apps.


### macOS (.app, .dmg, .pkg)

`packaging/macos/build-macos-package.sh` creates a `5DO.app` with an `Info.plist`
document type/UTI for the disc extensions, a drag-to-Applications `.dmg`, and a
`.pkg`. Without `--sign-identity` the result is unsigned; with a Developer ID it is
hardened and optionally notarized.

```sh
bash packaging/macos/build-macos-package.sh \
  --bundle artifacts/bundle/osx-arm64 --rid osx-arm64 --version 1.6.0 \
  --output artifacts/installers \
  --sign-identity "Developer ID Application: Example (TEAMID)" \
  --notary-profile "5do-notary"
```

Signing uses `codesign --options runtime` with the JIT entitlements in
`packaging/macos/entitlements.plist`. Notarization uses `notarytool` and staples the
ticket to both artifacts. Without credentials, keep the unsigned `.dmg`/`.pkg` or use
the portable tarball.

## CI

`.github/workflows/build-bundle.yml` builds the Windows and Linux bundles on their
native runners and builds the macOS arm64 DMG on a macOS runner. The runners install
.NET 11, which also proves the self-contained apphosts work.
`.github/workflows/linux-packages.yml` turns the two Linux bundles into `.deb`, `.rpm`,
AppImage, and Flatpak artifacts for both architectures, validates their metadata,
installs the `.deb` to verify the desktop integration and each `.flatpak` to run the CLI
inside the sandbox, signs them when the GPG secret is configured, and publishes them as
GitHub release assets. There is no hosted package repository.
`.github/workflows/release.yml` publishes the bundles, the Linux packages, the
signatures, and the checksum manifests to the GitHub release.

The Windows/Linux archives and the macOS DMG are the portable bundles; the installer
scripts above are additive. Unsigned installers can be produced locally and in CI.
Authenticode signing, Developer ID signing, and notarization remain conditional on valid
certificates and an Apple developer account; Linux GPG signing remains conditional on
`LINUX_GPG_PRIVATE_KEY`. Without those credentials the portable bundles and unsigned
packages are the release artifacts.
