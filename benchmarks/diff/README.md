# Differential manifests

These manifests drive `tools/FiveDo.DiffHarness`. They are evidence definitions,
not product configuration.

- `smoke.json` - one title, 300 frames, one matched checkpoint. Use it as the fast
  health check after changing the harness, CLI checkpoint path, or reference
  staging.
- `showcase.json` - the five-title showcase with 3,000-frame checkpoints, a
  two-frame offset window, and checkpoint images.
- `samples5.json` - the local `J:/Panasonic 3DO` five-title TEST-07 panel:
  300 frames, checkpoints 60/120/300, fixed seed 1488, PC/CPSR/CD/audio
  comparison, and a 512-sample tolerance. The exact NTSC clock keeps sample deltas
  at zero through 300 frames, so the cumulative audio hash is gated here.
- `audio-probe.json` - one title at 3,000 frames with checkpoints 60/120/300/600/
  1000/2000/3000. It measures the reference field-clock quantization: sample
  counts match through 1,000 frames and drift by +1/+2 at 2,000/3,000. Audio is
  informational here by design.
- `samples5-input.json` - the same five titles with the generic
  `scripts/menu-advance.txt` input script at 900 frames. It proves the input
  plumbing applies the same buttons on both engines: 5/5 video hashes match at
  60/300/600, and input-dependent screens (Alone, Road Rash, Space Ace,
  Wolfenstein) change at 900. `samples5-noinput.json` is the control.
- `roadrash-noinput.json` - the one-title control that shows Road Rash's f=600
  divergence is not input-induced.
- `cd-cadence.json` - the 11 panel titles that first diverge on CD at f=300, run
  to 900 frames with checkpoints 300/600/900. It shows whether the 300-frame
  count difference is in-flight cadence or a growing read-schedule divergence.
- `samples5-long.json` - the same five local titles at 3,000 frames with
  checkpoints 60/300/1000/3000. Use it to separate boot-time PC drift from
  visible in-game divergence.
- `panel50.json` - the generated 50-title TEST-07 accuracy panel: evenly spaced
  titles from `full.json`, 300 frames, checkpoints 60/120/300, PC/CPSR/CD
  comparison, sample tolerance 512. It has been run end to end on the local
  corpus (50/50 captured, 0 errors, **50/50 matching every frame hash** at
  60/120/300, **50/50 PC/CPSR phase-aligned**; only CD cadence remains); use
  `--cleanup-iso` and a work directory on a large disk.
- `full.json` - the generated 594-disc collection manifest. Its `roots` object
  currently points at the machine-specific `J:/Panasonic 3DO` and
  `G:/MAME/MAME Software List CHDs/3do` paths; every title uses `${games}` or
  `${games2}` so only the roots need editing on another machine.
- `tierb-behind.json` - the first Tier B playability batch: the ten titles where
  5DO differed from 4DO or Phoenix, 36,000 frames each, with the generic
  `scripts/tierb-10min.txt` script. It is consumed by
  `python tools/playability-sweep.py`, not by `FiveDo.DiffHarness`; the runner
  captures 600/3,600/18,000/36,000 frames and writes a 5DO-only summary. See
  `docs/TestCorpus.md` 1.1bi.
- `tierb-panel.json` - the next Tier B batch, generated by
  `python tools/build-tierb-manifest.py`. It selects titles where 4DO and Phoenix
  both claim playability but 5DO only has automated loadability evidence, uses
  `--bios-auto` so the database picks the BIOS and input device, and is reviewed
  with `python tools/tierb-contact-sheet.py`.
- `p0-quality-batch.json` - the P0 quality-closure batch: BladeForce, Jurassic Park
  Interactive, Off-world Interceptor, PGA Tour 96, and Alone in the Dark, each with a
  boot-absolute title-specific script. It is consumed by
  `python tools/playability-sweep.py`; the results are recorded under
  `artifacts/p0-quality` and in `docs/TestCorpus.md` 1.1bp.

These manifests assume the local corpus and the BIOS at `bios/panafz1.bin`.
Relative paths resolve from the repository root. The harness stages the OperaCore
DLL and BIOS under `artifacts/diff/work/` and never modifies `References/` or the
disc collection.

Run:

```powershell
dotnet build src/FiveDo.Cli -c Release
dotnet build tools/FiveDo.DiffHarness -c Release

tools/FiveDo.DiffHarness/bin/Release/net11.0/FiveDo.DiffHarness.exe `
  run benchmarks/diff/smoke.json --out artifacts/diff/smoke

tools/FiveDo.DiffHarness/bin/Release/net11.0/FiveDo.DiffHarness.exe `
  run benchmarks/diff/showcase.json --out artifacts/diff/showcase

# TEST-07 panel: fixed seed, PC/CPSR/CD/audio comparison.
# Build the debug core first (see docs/DifferentialHarness.md section 2).
tools/FiveDo.DiffHarness/bin/Release/net11.0/FiveDo.DiffHarness.exe `
  run benchmarks/diff/samples5.json --out artifacts/diff/test07-samples5 `
  --no-images --seed 1488 --compare-cd `
  --core artifacts/diff/opera-build-current/OperaCore.dll
```

The reference core is paced at its 16.16 NTSC field rate (59.939987 Hz), so
3,000 frames take about 50 seconds per title. Use `--resume` to reuse captures.

After an intentional hash change, refresh the checked-in nightly baseline:

```powershell
tools/FiveDo.DiffHarness/bin/Release/net11.0/FiveDo.DiffHarness.exe `
  baseline --current artifacts/diff/nightly/report.json `
  --write benchmarks/diff/baseline/showcase-report.json
``` `--force` is required after
changing frame counts, checkpoints, options, or the image/offset diagnostics. For
a CORE-08 profile A/B, use fresh output directories so cached captures from the
other profile are not reused:

```powershell
tools/FiveDo.DiffHarness/bin/Release/net11.0/FiveDo.DiffHarness.exe `
  run benchmarks/diff/full.json --out artifacts/diff/full-compatible `
  --profile compatible --no-images --cleanup-iso --resume

tools/FiveDo.DiffHarness/bin/Release/net11.0/FiveDo.DiffHarness.exe `
  run benchmarks/diff/full.json --out artifacts/diff/full-accuracy `
  --profile accuracy --no-images --cleanup-iso --resume
```

For an isolated timing-mode A/B, use the same fresh-output pattern with
`--arm-timing freedo|arm60`, `--clio-timers freedo|opera`,
`--cel-timing freedo|opera`, or `--cd-timing freedo|opera`. The override is applied to
every 5DO capture and recorded in report provenance; the reference captures are reused
by `--resume`.

`--timer-trace` writes `fivedo.timers.txt`, `fivedo.reads.txt`, and
`opera.timers.txt`. `--cd-register-trace` writes `fivedo.cdreg.txt` and
`opera.cdreg.txt` with command, poll, status, and data accesses (cycle and PC); use
fresh output directories and `--force` when adding or removing either trace.

Regenerate the full manifest after changing the collection:

```powershell
tools/FiveDo.DiffHarness/bin/Release/net11.0/FiveDo.DiffHarness.exe manifest `
  --root "J:\Panasonic 3DO" `
  --root "G:\MAME\MAME Software List CHDs\3do" `
  --out benchmarks/diff/full.json --frames 3000 --checkpoint 3000
```

A full 594-title run at 3,000 frames is roughly 8-9 hours because the reference
core runs in real time; use the self-hosted nightly workflow and `--resume`.

See `docs/DifferentialHarness.md` for the schema, allowlist policy, report
formats, and current limitations.
